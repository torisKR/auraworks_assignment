# 인터랙션 디자인과 구현 판단

## 디자인 방향

제공된 교재 표지와 첫 배너를 중심에 두고, 이동 방향과 현재 선택 상태가 분명하게 보이도록 설계했습니다. 원본 아트워크를 편집하거나 대체하지 않습니다. 장식용 배경 효과 대신 타이포그래피, 색 대비, 선, 여백과 버튼의 상태를 사용합니다.

## 캐러셀

5개 슬라이드의 위치를 바꾸는 360ms CSS transition을 사용합니다. 나가는 슬라이드와 들어오는 슬라이드가 함께 보여 이동 방향을 알 수 있습니다. 전환 중 입력을 막지 않으며 텍스트는 90~180ms, 교재는 200ms 지연 후 절제된 순서로 나타납니다.

포인터를 8px 이상 수평으로 움직이면 드래그를 시작합니다. 세로 이동이 우세하면 제스처를 취소하고 브라우저의 세로 스크롤을 유지합니다. 시작 지점이 링크나 버튼인 경우 해당 클릭을 우선합니다. 이동 거리 또는 짧은 스와이프의 속도가 기준을 충족하면 이전·다음으로 이동하고, 기준 미달이면 원래 위치로 돌아옵니다. 드래그 직후의 클릭은 차단해 의도하지 않은 페이지 이동을 줄입니다.

터치는 처음 누른 이미지에 암시적으로 캡처될 수 있습니다. 캐러셀 영역으로 캡처를 옮길 때 이미지에서 버블링하는 `lostpointercapture`를 전체 취소로 처리하면 스와이프가 중단됩니다. 캡처 상실 이벤트의 `target`이 캐러셀 영역 자체인 경우에만 취소하도록 수정하고, 배포 화면의 터치 에뮬레이션에서 `1→2`, `1→5` 이동을 확인했습니다. 실기기와 추가 입력 시나리오의 확인 범위는 [추가 검증 결과](verification-results.md)에 정리했습니다.

자동 재생은 기본적으로 꺼져 있습니다. 사용자가 재생을 누른 경우에만 6초마다 이동합니다. `requestAnimationFrame`으로 진행선을 그리되 프레임마다 React state를 갱신하지 않습니다. hover, focus, 드래그, 비활성 탭에서는 진행 시간도 멈추고 재개하면 남은 시간을 이어갑니다. 명시적인 재생 시작은 버튼에 남은 focus로 인한 일시정지를 해제하며, 다음 focus 이동은 다시 일시정지합니다.

모바일은 원본 이미지의 기존 crop을 유지하고 아래 64px 컨트롤 영역을 추가했습니다. 이동·재생 버튼은 44px이며 이미지의 CTA와 겹치지 않습니다. 원본 이미지에 포함된 카운터는 데스크톱에서 실제 컨트롤로 덮고, 모바일 crop에서는 화면 밖으로 나갑니다.

## 접근성과 움직임

- 좌우 키로 이동하고 Home·End로 처음·마지막 슬라이드를 선택합니다. Escape는 자동 재생을 정지합니다.
- 키보드 전환과 `prefers-reduced-motion`에서는 전환 움직임을 생략합니다. 동작 줄이기를 설정하면 자동 재생 버튼도 비활성화합니다.
- 비활성 슬라이드는 `aria-hidden`과 `inert`로 읽기와 focus에서 제외합니다.
- 수동 이동은 현재 소식을 안내하고 자동 재생 중에는 반복적인 live region 안내를 끕니다.
- 카드, 메뉴, FAQ summary에 명확한 focus 표시를 제공합니다.

## 스토어의 반응 상태

카드의 교재 이미지는 포인터 hover에서 소폭 확대되고 상세 보기 표시가 나타납니다. 키보드 focus에는 확대 대신 명확한 상세 표시를 제공합니다. 메뉴는 현재 경로와 hover에 밑줄을 표시하며 교재 상세에서도 스토어 메뉴가 선택 상태입니다. CTA와 아이콘은 hover 색상과 누를 때의 작은 위치·크기 변화로 입력을 확인합니다. 새 팝업이나 알림을 불필요하게 추가하지 않습니다.

## 책임과 확장

`HeroBanner`는 이동, 재생과 제스처 상태를 맡고 `hero-slides.ts`는 콘텐츠를 보관합니다. 데이터 요청은 기존 `useTextbooks`와 Supabase 접근 계층에 유지했습니다. CSS의 `--motion-quick`, `--motion-slide`, `--motion-ease`가 같은 상호작용의 속도를 공유합니다. 이 단계에서는 별도 모션 라이브러리를 추가하지 않았습니다.

슬라이드 수가 많아지거나 CMS에서 배너를 관리하게 되면 활성 항목과 이웃만 렌더링하는 전략, 이미지 로딩 우선순위, 일정별 노출 규칙을 검토합니다. 현재 5개 항목에서는 단순한 순환 위치 계산으로 빠른 입력을 처리합니다.

## 면접 설명 예시

> 장식적인 움직임보다 사용자가 어느 소식으로 이동했는지 알 수 있는 방향 전환을 먼저 구현했습니다. CSS transition으로 전환 중 입력에 반응하고, 재생 진행선은 DOM ref로 갱신해 프레임마다 React를 다시 렌더링하지 않습니다. 모바일 스와이프는 세로 스크롤과 링크 클릭을 우선하며, 키보드와 동작 줄이기 설정에서는 즉시 전환합니다. 제공 에셋을 유지하면서 실제 조작과 접근성을 함께 다뤘습니다.

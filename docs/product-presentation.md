# 제품 문구와 알림 설계

## 공개 화면과 개발 문서

공개 사이트는 `HIDDEN KICE` 브랜드와 교재·학습 경험 중심의 문구를 사용합니다. 페이지 제목, 설명, Open Graph, FAQ, JSON-LD, `llms.txt`와 Markdown 안내에서 과제·데모·더미 표현을 제거했습니다. 과제의 구현 범위와 Supabase seed 사용 여부는 README와 개발 문서에 남깁니다.

FAQ의 화면·JSON-LD·Markdown은 `src/data/site-faq.ts`의 같은 데이터를 사용합니다. canonical과 Preview의 색인 제외 정책은 기존 설정을 유지합니다. 공개 문구를 바꾸는 것만으로 상품 정보가 서버에서 검증되거나 검색엔진에 색인되는 것은 아닙니다.

## 사용할 수 있는 기능에 맞춘 표현

- 로그인은 이메일·비밀번호와 공용 테스트 계정을 제거하고 게스트 입장으로 구성했습니다. `features/auth`가 화면을, `SiteShell`이 게스트 상태를 맡습니다. 실제 회원 인증은 준비 중으로 안내합니다.
- 상세의 가상 작성자·별점 후기를 교재 활용 가이드로 바꿨습니다. 챌린지의 가상 참여자 수 대신 기간과 학습 목표 수를 표시합니다.
- 주문·결제와 답안 사진 분석은 해당 기능 옆에서 준비 상태를 안내합니다. 배송 일정이나 교환 기간을 확정적으로 약속하는 문구도 제거했습니다.
- 교재 조회는 Supabase CSR, OMR은 연습 5문항 비교, 챌린지는 현재 화면의 체크 상태입니다. 요청 실패를 로컬 상품 데이터로 대체하지 않습니다.

제품처럼 보이는 화면과 실제 서버 기능의 완성을 구분합니다. 공개 UI에는 이용자가 다음 행동을 결정하는 데 필요한 상태를 표시하고, 면접에서는 아직 구현하지 않은 회원 인증·결제·기록 저장을 명확히 설명합니다.

## 알림의 문제와 변경

이전 헤더는 숫자 `1`을 고정 출력했습니다. 알림을 열어도 읽음 상태가 없었고, 소식 안에서 스토어로 이동할 수도 없었습니다.

지금은 알림을 열면 현재 표시되는 소식을 읽음 처리합니다. 미읽음 개수를 계산해 헤더에 전달하고, 0이면 배지를 숨깁니다. 알림 목록은 제목·날짜·본문·읽음 표시와 이동 링크를 제공합니다. 링크를 누르면 알림 창을 닫고 해당 페이지로 이동합니다. 모달 배경과 본문 색상을 지정해 내용이 분명하게 보이도록 했습니다.

| 위치                                           | 책임                                             |
| ---------------------------------------------- | ------------------------------------------------ |
| `data/notifications.ts`                        | 소식 ID, 문구, 날짜, 목적지                      |
| `hooks/use-notifications.ts`                   | 읽음 ID 조회·저장, 미읽음 개수, 저장소 변경 구독 |
| `features/notifications/notification-list.tsx` | 소식 표시와 링크 이동                            |
| `components/layout/site-shell.tsx`             | 알림 열기·읽음 처리·닫기 조합                    |
| `components/store/site-header.tsx`             | 실제 미읽음 개수와 접근성 이름 표시              |

읽음 ID는 `hidden-kice:read-notifications` 키로 로컬 저장소에 보관합니다. 계정이나 개인정보는 기록하지 않습니다. 새로고침 후에도 읽은 소식의 ID를 확인하며, 같은 창은 커스텀 이벤트, 다른 탭은 `storage` 이벤트로 변경을 구독합니다.

`useSyncExternalStore`는 문자열 스냅샷을 사용합니다. 서버에서는 고정된 빈 목록 문자열을 반환해 초기 렌더 불일치를 방지합니다. 잘못된 JSON은 빈 목록으로 처리하고, 저장소 접근이 차단돼도 메모리 상태에서 읽음 처리를 유지합니다. 이 동작에 맞춰 개인정보처리 안내도 갱신했습니다.

## 확장과 면접 설명

회원 알림으로 확장할 때는 서버의 알림·수신자·읽음 기록을 분리하고 사용자별 RLS를 적용합니다. 로컬 읽음 상태를 서버 인증이나 회원 권한으로 사용하지 않습니다. 페이지네이션이 생기면 화면에 표시된 알림만 읽음 처리하고, 서버의 미읽음 집계를 함께 조회합니다.

> 고정 배지를 실제 상태와 연결했습니다. 콘텐츠, 읽음 상태, 표시를 분리하고 새로고침과 다른 탭의 변경도 반영합니다. 저장소가 차단돼도 화면은 동작하며, 회원 알림으로 확장할 때는 현재 표시 컴포넌트를 유지하고 읽음 기록을 서버와 RLS로 옮길 수 있습니다.

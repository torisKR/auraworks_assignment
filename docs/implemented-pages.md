상단과 푸터는 `SiteShell`에서 함께 제공합니다. Next.js의 `Link`로 이동하며 현재 메뉴를 표시합니다. 페이지 이동 중 데모 사용자와 장바구니 상태를 유지하고 새로고침하면 초기화합니다.

## 캐러셀

제공된 원본 배너를 첫 슬라이드로 사용하고, 교재 단품·패스·OMR·챌린지 소개를 추가해 총 5개로 구성했습니다. 추가 슬라이드는 제공 교재 이미지와 HTML 문구를 사용합니다.

- 이전·다음 버튼, 슬라이드 선택 점, 현재 순번을 제공합니다.
- 캐러셀 영역에 키보드 포커스를 둔 상태에서 좌우 방향키로 이동합니다.
- 자동 재생은 기본 정지 상태이며 사용자가 시작하면 6초 간격으로 이동합니다.
- 포인터가 배너에 있거나 배너 안에 포커스가 있으면 자동 이동을 잠시 멈춥니다.
- 숨겨진 브라우저 탭에서는 이동하지 않습니다.
- 선택 점을 직접 누르면 자동 재생을 정지합니다.
- 별도 이동 애니메이션을 사용하지 않아 움직임 감소 설정에서도 조작할 수 있습니다.

## Supabase 검색과 400ms 스로틀

`useThrottledSearch → useTextbooks(query, category) → fetchTextbooks → Supabase` 흐름입니다. 현재 화면은 전체 배열을 가져와 로컬에서 검색하는 방식에서 서버 검색 방식으로 변경했습니다.

1. 입력값은 즉시 검색창에 표시합니다.
2. 첫 입력은 바로 조회 조건에 반영합니다.
3. 연속 입력은 400ms 구간 안에서 마지막 값을 예약합니다. 입력할 때마다 종료 시점을 뒤로 미루는 디바운스와 달리 처음 정한 구간이 끝나면 최신 값이 전달됩니다.
4. 검색어 지우기는 즉시 적용하고 예약된 이전 입력을 취소합니다.
5. 제목과 과목의 대소문자 구분 없는 부분 일치 조건을 OR로 묶고, 종류는 `eq` 조건으로 함께 적용합니다.
6. 검색 값의 한글·공백을 정규화하고 PostgREST 구문용 따옴표와 LIKE 예약 문자를 처리합니다.
7. 조회 조건이 달라지면 이전 요청을 취소하고 응답이 돌아와도 취소된 결과는 반영하지 않습니다.

검색 대기·조회 중 안내, 조회 실패와 재시도, 빈 결과를 구분합니다. 페이지네이션과 URL 검색 조건 복원은 아직 향후 확장 범위입니다.

참고: [Supabase OR](https://supabase.com/docs/reference/javascript/using-filters-or), [ILIKE](https://supabase.com/docs/reference/javascript/using-filters-ilike).

## 데모 로그인

공용 계정은 `demo@hiddenkice.test`, 데모 비밀번호는 `hiddenkice2026`입니다. 입력 없이 데모 체험 버튼으로도 로그인할 수 있습니다.

실제 Supabase Auth 로그인은 아닙니다. 입력값은 서버에 보내거나 저장하지 않으며 성공 시 비밀번호 상태를 지웁니다. 화면 전체에서 사용하는 데모 사용자만 메모리에 보관합니다. 실제 계정 정보를 입력하지 않도록 폼에 안내합니다.

## 상세 데이터 구분

- Supabase: 교재 ID, 제목, 종류, 과목, 설명, 이미지, 가격, 표시 순서
- `src/data/textbook-details.ts`: 데모 출판 정보, 목차, 학습 포인트, 후기

DB 조회에 실패할 때 상세 더미 배열로 대체하지 않습니다. 잘못된 ID와 존재하지 않는 교재는 찾을 수 없음 화면을 표시하고 스토어로 돌아갈 수 있습니다. 목차와 후기가 실제 상품 정보로 보이지 않도록 예시 표시를 넣었습니다.

## OMR과 챌린지

OMR은 준비된 정답과 선택한 답을 브라우저에서 비교하는 데모입니다. 실제 AI 모델 호출·파일 업로드·개인 답안 저장은 없습니다. 모든 문항을 선택하면 채점 버튼이 활성화됩니다.

챌린지 데이터와 참여자 수는 예시입니다. 데모 로그인 상태에서만 참여 버튼을 제공합니다. 참여 후 목표 체크와 진행 상태를 확인할 수 있습니다. 챌린지 화면을 떠나거나 새로고침하면 해당 체험 기록은 초기화됩니다.

약관과 개인정보 안내도 이 범위를 기준으로 작성한 예시 문서이며 실제 판매·회원 서비스용 법률 문서는 아닙니다.

## 검증과 시연 체크리스트

코드 검사, 단위 테스트와 프로덕션 빌드 통과를 확인했습니다. 실제 브라우저에서 새 기능을 확인하려면 아래를 순서대로 시연합니다.

1. 다음 슬라이드·선택 점·좌우 키·재생과 정지를 확인합니다.
2. 검색어를 빠르게 입력하고 마지막 검색어로 요청되는지 Network에서 확인합니다.
3. `수학` 검색과 `단품` 종류를 함께 선택해 결과 한 개를 확인합니다.
4. 없는 검색어, 특수문자 입력, 검색어 지우기, 네트워크 오류와 재시도를 확인합니다.
5. 카드에서 상세로 이동하고 목차·후기·장바구니를 확인합니다.
6. 로그인 실패, 데모 로그인, 페이지 이동 후 유지, 로그아웃을 확인합니다.
7. OMR 5문항을 선택해 결과와 초기화를 확인합니다.
8. 챌린지 참여·목표 체크·취소를 확인합니다.
9. 모든 메뉴와 푸터 링크, 모바일 화면, 키보드 포커스를 확인합니다.

실제 Auth·주문·결제·AI 분석은 [향후 기능 계획](future-extension.md)에서 따로 설명합니다.

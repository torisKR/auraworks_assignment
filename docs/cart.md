# 장바구니 구현과 면접 설명

## 현재 구현

상세의 담기 버튼은 교재를 추가하고 확인 창을 엽니다. 동일 교재는 중복 행을 만들지 않고 수량을 합칩니다. 상단 장바구니 아이콘과 확인 창의 링크로 `/cart`에 진입합니다. 헤더 숫자는 교재 종류 수가 아닌 전체 수량입니다.

- 교재별 1~99권 증감, 개별·전체 선택, 개별·선택 삭제
- 선택된 판매 가능 교재만 수량·정가·할인액·교재 합계에 포함
- 새로고침 복원과 같은 출처의 다른 탭 변경 반영
- 로딩·빈 상태·조회 오류와 재시도·판매 중단 교재 표시
- 주문 버튼은 준비 중이며 주문 생성·결제·배송비 계산은 구현하지 않음

할인액은 DB의 `original_price`와 `price` 차액으로 계산합니다. 기존 제공 이미지의 할인율 배지는 seed 표시값이라 금액 차액과 일치하지 않을 수 있습니다. 실제 판매 전 할인 정책과 seed를 정합하게 맞춰야 합니다.

## 역할과 데이터 흐름

```text
상세 담기 / CartContent 수량·선택·삭제
  → SiteShell이 제공하는 useCart
  → lib/cart.ts에서 수량·저장값 검증
  → localStorage: hidden-kice:cart:v1
  → 교재 ID 목록을 fetchCartTextbooks에 전달
  → Supabase SELECT + 공개 카탈로그 RLS
  → 현재 교재와 결합 → 선택 금액 표시
```

`CartEntry`는 `{ textbookId, quantity, selected }`입니다. 가격·제목·회원 정보는 저장하지 않습니다. 전체 상품 객체를 오래 보관하면 가격 변경이나 판매 중단을 화면에 반영하기 어려우므로 ID와 구매 의도만 저장합니다. 조회 결과를 결합한 `CartLine`에서 교재가 없으면 `textbook: null`로 표시합니다.

`useSyncExternalStore`로 저장 문자열을 구독합니다. 서버 스냅샷은 고정된 빈 배열 문자열이고 초기 클라이언트도 같은 값을 사용한 다음 브라우저 저장값을 읽습니다. 매번 새로운 배열을 스냅샷으로 반환하지 않아 반복 렌더를 방지합니다. 저장값은 반환 후 순수 함수로 파싱합니다.

저장소 변경은 같은 탭의 커스텀 이벤트와 다른 탭의 `storage` 이벤트로 반영합니다. 변경할 때 최신 저장 문자열을 다시 읽어 연속 클릭이 이전 렌더의 수량을 덮어쓰지 않도록 합니다. 여러 탭의 완전히 동시인 쓰기는 마지막 쓰기가 반영되며, 서버 트랜잭션 같은 동시성 보장은 없습니다.

## 실패 처리

잘못된 JSON·UUID·음수·소수 수량은 버리고 중복 저장 항목은 수량을 합쳐 최대 99권으로 제한합니다. 로컬 저장값에 가격을 추가해도 계산에 사용하지 않습니다. 저장 권한이 없거나 용량이 부족하면 현재 브라우저 세션의 메모리로 유지하고 새로고침 복원이 불가능함을 안내합니다.

조회 키는 정렬한 교재 ID 목록과 재시도 버전입니다. 수량·선택 변경은 같은 교재 조회를 반복하지 않습니다. 조회 조건이 바뀌면 이전 결과를 새 조건의 성공 화면으로 표시하지 않으며, 요청을 취소하고 취소된 응답은 반영하지 않습니다. 조회 실패를 임의 가격으로 대체하지 않습니다. 오류 중에도 삭제와 선택 삭제는 가능합니다.

## 회원·주문으로 확장하기

회원 인증을 추가하면 `cart_items`에 사용자 ID·교재 ID·수량을 저장하고 사용자별 RLS로 본인 행만 읽고 수정하도록 만듭니다. UI와 순수 계산 함수를 유지하면서 저장·조회 책임을 변경할 수 있습니다. 로그인 시 비회원/회원 항목 병합 규칙, 중복 병합 방지, 최대 수량, 로그아웃 후 이전 회원 캐시 제거를 먼저 정합니다.

현재 Supabase의 CSR 가격 조회는 표시를 위한 것입니다. 클라이언트나 로컬 저장값은 주문 금액의 신뢰 경계가 아닙니다. 주문 API가 DB 가격·판매 여부·재고를 다시 확인하고 주문 항목과 총액을 트랜잭션으로 확정해야 합니다. 결제에는 멱등성 키와 검증된 webhook 처리가 추가로 필요합니다.

## 면접 답변 예시

“비회원도 새로고침 후 교재 선택을 이어갈 수 있도록 ID·수량·선택만 브라우저에 저장했습니다. 가격은 Supabase에서 CSR로 다시 조회하고, 삭제된 교재는 합계에서 제외해 상태를 표시합니다. 화면, 저장·요청 훅, 순수 계산과 타입을 분리했습니다. 회원 기능에서는 저장 책임을 사용자별 RLS가 적용된 테이블로 바꾸고, 결제 금액은 서버에서 재검증할 계획입니다.”

## 검증 범위

ESLint·TypeScript와 전체 단위 테스트 17개, Next.js 프로덕션 빌드를 통과했습니다. 장바구니 테스트 5개는 중복 담기·수량 경계·손상 데이터 복구·가격 변경·판매 중단·선택 합계·저장 계약을 검증합니다. 실제 브라우저 조작과 배포 확인은 별도 증거로 기록하며 단위 테스트를 브라우저 검증으로 설명하지 않습니다.
